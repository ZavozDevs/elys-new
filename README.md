# Elys

Помощник **внутри твоего аккаунта Telegram**. Ты пишешь команду — Elys выполняет её.
Собеседники управлять им не могут: команды работают только из твоих сообщений.

## Начать

Нужен Python 3.11 или новее. В папке проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m elys
```

Мастер объяснит, как войти в аккаунт. Ключи и код входа вводи только в своём терминале,
никому их не пересылай. Файлы в `data/` содержат доступ к аккаунту — не публикуй их.

После запуска напиши в Telegram:

- `.ping` — проверить, что Elys отвечает;
- `.help` — увидеть команды и объяснения;
- `.help Ping` — узнать о конкретном модуле;
- `.config` — открыть настройки Elys и модулей: всё в одном меню с кнопками.

Команда — обычное сообщение с точкой в начале. Писать можно в любом чате,
но ответы там видят его участники. Для личных команд используй «Избранное»: команды работают и там.
Остановить программу в терминале — `Ctrl+C`.

## Добавить новые команды

**Модуль** — файл с кодом, который добавляет возможности. Он получает полный доступ
к аккаунту и компьютеру, где работает Elys. Ни `--trust`, ни автоматическая проверка
синтаксиса не делают чужой код безопасным. Выбирай только доверенных авторов.

1. Получи файл `hello.py` от автора или прямую ссылку на него.
2. Ответь на файл командой `.dlm --trust`. Для ссылки:
   `.dlm https://example.org/hello.py --trust` (замени пример настоящей ссылкой).
3. Elys покажет имя модуля и команду справки, например `.help Hello`.

Можно установить файл или папку с сервера: `.dlm /путь/hello.py --trust`.
Папка должна содержать `__init__.py`. Архивы не распаковываются.
Если путь содержит пробелы — возьми его в кавычки.

| Команда | Что делает |
|---|---|
| `.lm` | показывает встроенные и установленные модули |
| `.ulm Hello` | выключает модуль, сохраняя его файл и настройки |
| `.lm hello` | включает его снова по **имени файла без .py** |
| `.dlm … --trust` | устанавливает новую версию того же файла |
| `.reload Hello` | перечитывает код с диска |
| `.rollback Hello` | возвращает предыдущую версию кода |
| `.ulm Hello --purge --yes` | выключает и безвозвратно стирает данные и настройки модуля |

Выключенные модули не запускаются после перезапуска. Встроенные выключить нельзя —
они нужны для управления Elys. При неудачной замене загрузчик восстанавливает код
предыдущей рабочей версии. Откат **не отменяет** изменения данных, отправленные
сообщения, установку зависимостей и другие действия стороннего кода.

## Настроить под себя

Напиши `.config` или нажми «Настройки» в закреплённом приветствии чата **Elys**.

- **Настройки Elys** — начало команды (например `!` или несколько вариантов `. !`),
  язык, картинки над ответами, сокращения команд и картинка приветствия.
- **Настройки модулей** — выбери модуль, затем нужный параметр. Можно сразу написать
  `.config Ping`. Переключатели и готовые варианты меняются кнопками; есть возврат
  к значению по умолчанию с подтверждением.
- Для ввода текста нажми «Изменить», перейди в чат Elys и **ответь на подсказку**.
  На ответ есть 3 минуты. «Отмена» в меню или ответ `/cancel` прекращает ввод.
  Секретные значения скрыты, сообщение с введённым секретом удаляется до сохранения.
  Для ввода в служебном чате должны оставаться только ты и бот.

Меню видно участникам чата, где оно открыто, но нажимать его кнопки можешь только ты.
После смены начала команды подсказки обновляются. Изменения сохраняются сами, старые
настройки из `.prefs` подхватываются автоматически; отдельной команды `.prefs` больше нет.
Картинки не появятся без ссылки на баннер в настройках модуля.

### Чат Elys и бот-помощник

При запуске Elys создаёт бота через официальный Web App @BotFather и включает
inline-режим исходящими HTTPS-запросами, без браузера, открытых портов и бота-управляющего.
API Web App внутренний; при его изменении понадобится обновление Elys. Если Web App
отказывает создать бота, Elys создаёт его командой `/newbot` в чате с @BotFather и сразу
стирает всю переписку у обоих участников (в ней виден токен); остальное — снова через Web App. Проверка
`/start` и ответ удаляются у обоих участников; пустой диалог с ботом остаётся.
Бот отвечает в личке только тебе, остальным — молчит.

Основное общение — в автоматически созданном форуме **Elys**: «Начало», «Ошибки»,
«Обновления», «Копии». Последние две темы пока подготовлены для следующего этапа:
самих обновлятора и резервного копирования ещё нет. Elys сначала ищет уже существующие
форум «Elys» и своего бота и подключает их друг к другу, создавая только недостающее:
если выгнать бота, он вернётся в тот же форум; темы определяются по названию, лишь
пропавшие создаются заново. Форум создаётся заново, только если его удалили. Важные сообщения при
недоступном форуме направляются в личку; если доставка невозможна — в терминал и лог.

**Статус проверки:** локальные тесты выполняются без Telegram. Авторизация в настоящем
Web App BotFather, чтение токена существующего бота, включение inline, поиск существующих
форума и бота и подхват тем проверены на настоящем аккаунте. **Создание бота через Web App
сейчас отказывает** (`createBot` → `{"error":"Error"}` даже у настоящей страницы BotFather;
возможная причина — сессия моложе 24 часов, не подтверждено). Запасное создание через `/newbot`
с удалением переписки проверено только тестами. Восстановление удалённого
форума и внешний вид премиум-эмодзи пока **не проверены**.
Сценарий ручной приёмки: [tests/TELEGRAM_STAGE3.md](tests/TELEGRAM_STAGE3.md).

## Написать небольшой модуль

Рабочий пример: [`examples/hello.py`](examples/hello.py).
Установка из папки проекта: `.dlm examples/hello.py --trust`.

Публичный API импортируется из `elys`:

- `Module(name, version=…, author=…, requires=[…], config=…, strings=…, banner=…)`;
- `@module.command(name, aliases=(), roles=())` — роль пока не даёт другим людям доступ;
- `on_message`, `on_edited_message` с `scope=Scope.…`, `on_deleted_messages`, `on_raw_update`;
- `on_load`, `on_ready`, `on_unload` — асинхронные функции с аргументом `client`;
- `@module.loop(seconds, autostart=False)`; `loop.start()`, `await loop.stop()`;
- `module.spawn(coro)` — отслеживаемая задача; `module.db` — сохраняемый словарь;
- `Config(value=Config.value(1))`, `Config.secret`, `Config.choice`, `Config.url`;
- `module.t(key, **values)` — текущий язык → ru → en → ключ; аргументы экранируются;
- `html.b/i/code/pre/quote/link/emoji/escape`, `E.check`, `E["check"]`;
- `await respond(message, text, banner=url)` — редактирует своё сообщение или отвечает на чужое.

`requires` и `banner` должны быть литералами прямо в вызове `Module` на верхнем уровне.
Зависимости указываются именами PyPI, не URL или флагами pip. Для загрузчика нужен pip
в том же окружении Python. Зависимости ставятся до импорта модуля.

Декораторы сами ресурсы не регистрируют. `module.client`, `module.db`, `module.app`
доступны с `on_load`. `on_ready` вызывается после регистрации; при старте встроенные
модули уже доступны. Рендери `E.check` внутри функций, не на уровне импорта: так он
учтёт актуальный статус Premium. Без Premium используются обычные эмодзи.

Задачи создавай через `module.spawn`/`module.loop`, хендлеры — через декораторы:
тогда выгрузка их дождётся и удалит. Произвольные `asyncio.create_task` и прямые
`client.add_handler` загрузчик не контролирует. Вотчер без `scope` получает отметку
«слушает все сообщения». Тяжёлую работу выноси из вотчера в `module.spawn`.

Инлайн-интерфейс (пример: [`examples/menu.py`](examples/menu.py)):

- `await module.form(message, text, [[Button("Название", callback, data=…)]])`;
- `await module.list(message, ["Страница 1", "Страница 2"])`;
- `await module.gallery(message, [Photo("https://…", "Подпись")])`;
- кнопка вызывает обычную `async def callback(bot, query, data)`; для изменения текста
  и кнопок вместе — `await module.app.inline.edit(query, text, buttons)`;
- `Button(..., style="primary" | "success" | "danger", icon="check")`. В сообщениях, которые
  отправил сам бот (меню в форуме Elys), при Premium у владельца это настоящая премиум-иконка.
  Telegram не принимает её в inline-сообщениях (все формы в твоих чатах), поэтому там перед
  текстом кнопки ставится обычный эмодзи из реестра;
- формы живут 24 часа, при выгрузке модуля удаляются. По умолчанию нажимает только
  владелец; доступ другим людям нужно явно разрешать через `allowed_ids=[…]`;
- `@module.callback(prefix)` и `@module.inline(query)` работают на bot-клиенте,
  до этапа безопасности доступ к ним — только у владельца.

Секреты и служебные данные не включай в текст формы: сам текст виден всему чату.
После перезапуска старые формы нужно открыть заново.

Премиум-эмодзи в формах, списках и подписях галерей показываются сразу. Telegram вырезает
их из inline-результата, поэтому Elys (если у владельца есть Premium) отправляет ⭐ и тут же
правит сообщение полным текстом. Для этого у бота включается Inline Feedback (100%): без
него Telegram не сообщает бот-у, какое сообщение отправлено. Фиксированной паузы нет.

## Проверить изменения

```sh
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
.venv/bin/lint-imports
```

Тесты работают без Telegram-аккаунта: используют настоящий диспетчер wzgram,
локальный HTTP-сервер и изолированное окружение pip. Внешний вид премиум-эмодзи и
баннеров нужно дополнительно проверять в Telegram; локальные тесты проверяют HTML
и параметры, но не отображение на сервере.
